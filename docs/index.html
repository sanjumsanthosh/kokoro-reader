A desktop reader for long Markdown — agent output, design docs, release notes. It renders the text, narrates it with Kokoro‑82M running locally, and caches every clip so re‑reading a document costs nothing but a click.

Phase one — cache queue rewrite

Before, the cache panel exposed every audio clip as its own row, so a single article could scatter into dozens of entries. Now clips are grouped into one row per article, with the next incomplete clip ready to continue.

Read state moved from a boolean to timestamps, and storage now reports physical bytes — shared WAV files counted once, not once per article…

what it does

Built for documents, not sentences

Paste a Markdown file, split it into sections, give each section its own speech text, and let the player walk you through it.

Offline narration

Kokoro‑82M (fp32, 24 kHz) runs in Rust. One model download, then zero network.

Section‑aligned speech

Click a paragraph, hear that paragraph. The narration layer sits beside the source, not inside it.

Audio cache queue

Cached, queued, caching, failed — grouped per article, with a retry that only redoes what broke.

Real player controls

Three voices, 0.5–2.0× speed, per‑section restart, jump to marker, 5‑second seek.

Library with read state

Date added, date marked read, cached audio size, batch delete — a reading list, not a file browser.

Honest storage

Physical disk accounting for models, cache, and projects. Shared files counted once.

run it

Three commands, one download

# macOS · Rust + Bun + Tauri 2
$ git clone https://github.com/sanjumsanthosh/kokoro-reader
$ cd kokoro-reader && bun install
$ bun run tauri dev

# first launch: “Set up offline speech”
# download the model once, then it's local forever
Privacy: the network is used exactly once, to fetch the speech model. Documents, narration, and audio stay in the app support directory — no telemetry, no accounts, no sync.

guard rails

Deliberate limits

2 MB per document

Bigger than a chapter, smaller than a lawsuit.

510 tokens per sentence

Long sentences are split before synthesis, never truncated.

2 GB audio cache

Old clips are pruned; shared clips survive as long as one article needs them.
